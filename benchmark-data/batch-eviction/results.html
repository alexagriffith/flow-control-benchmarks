Flow control batch eviction benchmark

Can flow control protect realtime p95 TTFT while batch workloads share the same GPU?

Flow control protects higher-priority realtime p95 TTFT through reserved capacity and batch eviction. When realtime demand needs capacity, lower-priority batch work is evicted, retried, and completed later.

Batch workloads can use shared GPU capacity while flow control returns capacity to realtime traffic when demand arrives.

Capability boundary

The evidence supports a production pattern and defines its operating limits.

Supported by these tests

  • Protect realtime with reserved capacity. The median p95 TTFT decreased from 561 ms to 341 ms.
  • Reclaim running negative-priority work. Eviction terminated the selected vLLM streams.
  • Retry batch to completion. All 38 evicted jobs completed with zero duplicate results.

Evidence limits

  • Eviction needs a retry owner. The Endpoint Picker terminates the stream; the Async Processor resubmits it.
  • Reserved capacity produced the latency result. Eviction recovered batch work that was already running.
  • The proof covers one model replica. Cross-node queue recovery and multi-replica reclamation were outside this benchmark.

Method, configuration, and evidence gate

Model service

  • One NVIDIA H100 GPU
  • GPT-OSS 20B
  • Red Hat AI 3.4 vLLM
  • max-num-seqs: 96
  • max-num-batched-tokens: 8,192

Policy and traffic

  • Endpoint Picker with batch eviction enabled
  • maxConcurrency: 48
  • Configured priorities: 100, 0, -10; measured traffic used 100 and -10
  • Initial burst followed by seeded open-loop Poisson traffic with a sinusoidally varying rate
  • Prefix caching disabled and verified

Required evidence

  • Client timing and status
  • Endpoint Picker queue and eviction
  • Envoy request identifier routing
  • vLLM running, waiting, KV cache, and preemption
  • Async retry, final result, deadline, and duplicate checks
Evidence captured August 2026. The matched proof contains 12 accepted runs. All 12 data audits passed; 10 met the stricter all-realtime-success performance gate. No fixed service-level objective is claimed.
