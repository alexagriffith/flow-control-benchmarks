Flow control evidence, tied together

Three benchmark campaigns establish priority behavior, production configuration choices, and safe recovery for batch work that is already running.

What each campaign adds

The absolute latency values are specific to each model, GPU, request shape, and offered load. Compare mechanisms within a matched campaign.

RHAII 3.4 flow control

Priority and queueing baseline

Higher-priority traffic dispatches first while batch absorbs the wait.

The gate removed 48,224 batch HTTP 429 responses at the same offered load. Same-priority fairness prevented starvation but did not create a separate latency tier.

Endpoint Picker v0.9.0

Configuration and production traffic

Request-count admission protected steady realtime tenants across four production-shaped scenarios.

Engine, detector, admission, workload-shape, mixed-traffic, routing, stability, and model-pool tests define where each setting helps and where it does not.

Batch eviction build

Recovery for work already in vLLM

Reserved capacity protected realtime p95 TTFT while evicted batch work was retried reliably.

The one-model-replica proof reproduced across three repeats. A two-model-replica follow-up confirms the mechanism across a shared model pool.
